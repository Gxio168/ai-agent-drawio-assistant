# 项目开发规范

本文适用于整个仓库。开始修改前先阅读本文及相关模块代码；若子目录另有 `AGENTS.md`，同时遵循其更具体的要求。本文与用户明确提出的要求冲突时，以用户要求为准。

## 项目概况

- 本项目是基于 Java 17、Spring Boot 3.4.3 和 Maven 的多模块 DDD 工程，根 `pom.xml` 负责聚合模块和依赖版本管理。
- 模块结构和当前实现概况见根目录 [`PROJECT_STRUCTURE.md`](PROJECT_STRUCTURE.md)。涉及模块职责变化时同步更新该文档。
- Java 主包名为 `cn.bugstack.ai`。新增代码沿用相邻代码的包结构、格式和命名风格。

## 分层与依赖

- `api`：跨边界服务契约、DTO 和统一响应模型。不要在这里实现业务流程。
- `trigger`：HTTP 等入口适配、参数接收与结果映射；调用领域服务完成用例。不要在 Controller 中编排核心业务或访问存储。
- `domain`：Agent、会话、对话及装配等业务规则、领域模型和服务。领域代码不应依赖 `trigger`、具体 DAO 或 HTTP 请求对象；需要外部能力时优先定义端口，再由基础设施提供实现。
- `infrastructure`：实现领域端口，封装数据库、缓存、文件及外部服务访问。不要把存储实现泄漏到领域模型或 API 契约中。当前本模块的 Repository、DAO、Gateway 主要是预留结构，新增实现应按实际接入完善。
- `app`：启动入口、Spring 配置、依赖装配和环境资源；不要将业务规则放入启动类或配置类。
- `types`：确有跨模块复用需要的基础常量、错误码和异常。避免将某个业务域专用的类型放入此模块。
- 依赖保持单向：`trigger` 可依赖 `api`、`domain` 和 `types`；`infrastructure` 依赖 `domain`；`app` 组装运行所需模块。禁止循环依赖。新增模块依赖时同步检查对应 Maven POM。

## 编码约定

- 优先扩展现有领域和模块，不重复创建同职责的服务、模型或转换逻辑。
- 命名清晰表达用途；沿用现有约定：接口常以 `I` 开头，传输对象用 `DTO`，领域实体用 `Entity`，值对象用 `VO`。包名小写，类型名使用 `UpperCamelCase`，方法和字段使用 `lowerCamelCase`。
- API 输入输出使用明确的请求/响应 DTO；不要将数据库 PO 或领域内部对象直接暴露给接口调用方。
- 使用项目统一的响应结构和 `ResponseCode` / `AppException` 错误语义。不要吞掉异常；在入口层转换为对外响应，并保留有用的上下文日志。日志不得包含密钥、令牌或不必要的用户敏感数据。
- 配置放在对应配置类或 `src/main/resources/application*.yml`、Agent 资源目录中。环境差异通过 profile 配置；禁止提交真实凭据，新增配置项应提供安全的占位值或环境变量引用。
- 保持改动聚焦，避免无关格式化、批量重命名或顺手清理与任务无关的代码。

## 修改与交付

- 新增或改变行为时，在对应模块补充或更新测试；测试代码放在该模块的 `src/test/`。不要仅为满足覆盖率添加无行为断言的测试。
- 文档、接口契约、配置或部署方式发生变化时，更新相关说明；模块总览变化时更新 `PROJECT_STRUCTURE.md`。
- 修改前检查工作区现有改动，保留用户已有内容；完成后检查变更范围和差异，说明做了什么及是否运行验证。
- 未经用户要求，不执行部署、发布、数据清理等高影响操作；不新增未被本任务要求的依赖。
